# 户型识别、校准与布置详细流程

从主SKILL按需进入；生成前始终先读 `spec-format.md`。

### 0. 先看是哪种图，选识别路线

| 输入 | 路线 |
|---|---|
| **CAD 导出的矢量 PDF**（放大不糊；`fitz` 的 `get_drawings()` 有几千个图元）、**DXF** | 走 **CAD 路线**（下面 2C）：`cadvec.py` 直接读图元坐标，墙、门窗洞口精确到 mm，不用像素比例和 axismap |
| **一页上并排好几层平面**（别墅、自建房、联排的一层 / 二层……），或**描边墙在每个交接处都断开**（量房软件导出、cadvec 报“没认出墙厚”或墙认不全） | 走 **整栋楼路线**（下面 2D）：`cadsplit.py` 按楼层切开、识别描边墙、各层自动对齐，输出整栋楼初稿 |
| DWG | 让用户另存为 DXF，或用看图软件 / 网页导出 **SVG**（SVG 是真实毫米坐标、按图层分色，最准），再走 CAD / 整栋楼路线；实在不行打印成 PDF |
| 图片、截图（含黑底 CAD 截图）、扫描件、只有位图的 PDF | 走图片路线（下面 2）：PDF 先渲染成 PNG（`fitz` 200dpi） |

CAD 图纸的画法（涂黑 = 钢筋混凝土 / 承重、砖纹填充 = 新砌墙、3~4 线 = 窗、弧线 = 平开门、⊠ = 烟道管井、⊕ = 地漏、45° 斜杠 = 尺寸起止符号、三道尺寸、轴线）
和人工核对清单见 `reference/cad-conventions.md`，**走 CAD 路线前必读**。

### 1. 读图

查看户型图，记下：
- 最外圈总尺寸（总宽、总深 mm），以及分段尺寸
- 每个房间的名字和位置，门（开向、门轴在哪端）、窗、推拉门、入户门
- 门窗的具体类型：子母门、折叠门、隐形门；平开窗、推拉窗、落地窗、高窗、飘窗（判断方法见格式说明“门窗”一节）
- 承重墙（多数户型图用黑色/深色实心表示），柱、烟道、管井
- 指北针方向（写进 `north`）；用户提到城市就写进 `site`，日照模拟会按当地纬度算
- 图上标的面积，用来事后核对

图没有任何尺寸时，问用户要一个已知尺寸（比如某面墙多长），或者按常见尺寸估算，并且在交付时说明比例是估的。

### 2. 自动识别墙体（初稿 + 比例）

```bash
python scripts/analyze.py 户型图.jpg --total-width 12340 --total-height 11940 --out <工作目录>/analysis
```

- 输出 `mmPerPx`（比例），`scale_check` 里是按宽、按深分别算的比例。两者差 2% 以内说明比例可信。
  差得多通常是因为有凸出部分（飘窗、阳台）超出了总尺寸的范围：改用 `--dim 像素x0 像素x1 毫米`，按某一段标注线两端的像素位置定比例。
- `analysis.png`：原图 + 识别出的墙段（W 编号，红色 = 承重墙，橙色 = 非承重）+ 断口（G 编号，门窗候选）+ 尺寸线刻度（T/B/L/R 编号的紫色圈）+ 像素标尺，用来读坐标。
- **承重墙**：脚本按墙芯颜色自动分两类（深色 = 承重，`bearing_by: "color"`）。图上所有墙同一个颜色时只能按厚度猜（`bearing_by: "thickness"`），
  这些墙在 analysis.png 上编号带 `?`、也列在输出的 `bearing_unsure` 里——**必须对照原图图例逐面确认**（图例常写“承重墙 / 非承重墙 / 新建墙”）。
  常见画法：承重墙黑色或深灰实心、斜线填充；非承重墙浅灰实心或只画两条边线；外墙一般按承重处理；厨卫的 100~120mm 薄墙基本是非承重。
  颜色分界不对时用 `--bearing-max 亮度` 手动指定（承重墙颜色的最大亮度，0~255）。
- 隔墙只画了两条细边线、中间是白的（贝壳等常见）：加 `--outlined`，否则这些墙会漏掉。
- `analysis.json` 的 `dims_px`：每条尺寸线上的刻度（尺寸界线）像素位置，下一步精确定位墙要用。
- `draft.json`：直接可用的 HouseSpec 初稿（墙 + 门窗候选 + 底图参数）。**识别会漏墙**，漏掉的通常是：被窗户打断的墙段、很细的隔墙、浅色玻璃隔断；门窗类型也只是猜测。
- 墙体颜色偏浅、识别不到时调 `--gray-max 200`。图例、logo 被误识别成墙时用 `--crop x0 y0 x1 y1` 限定范围。

### 2C. CAD 路线：矢量识别（PDF / DXF）

```bash
python scripts/cadvec.py 图纸.pdf --out <工作目录>/cad      # 图上有尺寸标注：自动读数字定比例、按标注定坐标
python scripts/cadvec.py 图纸.dxf --out <工作目录>/cad      # DXF：自带单位，标注图元（含改写的标注文字）直接用
python scripts/cadvec.py 图纸.pdf --total-width 10540 ...   # 读不出标注时才需要：最外道总尺寸（墙体外皮）
```

- **尺寸以标注数字为准（精度的关键）**：用户拿图纸上的数字逐个对设计器，**墙厚、每段墙、洞口、房间开间进深都必须等于标注**，不是“和图形差不多”。cadvec 的做法：
  1. 找全所有尺寸线（直线 + 落在线上的 45° 起止符号）和每个刻度的尺寸界线（界线另一头 = 被量的那个墙面）；
  2. 读出每段的数字：文字层直接读；没有文字层（SHX / TrueType 字体炸成轮廓，最常见）就用 `dimtext.py` 破译——同一张图同一个数字字形完全一样，按形状聚类，再用量出的长度投票“哪类字形是哪个数字”，挤在一起的两个数字（“390120”）会拆开分给相邻两段；读出的数字和图形差 > 12mm / 0.8% 的不用；
  3. 每个方向把所有标注当成“刻度之间的距离约束”做加权最小二乘：外侧分段最细的那道（门窗洞口细部尺寸）优先级最高，其次轴线尺寸、总尺寸，室内细部尺寸最低；明显读错的数字自动剔除；
  4. 墙面、洞口边离某个刻度 ~15mm 以内就直接取那个刻度的标注值（图上线和刻度常差几毫米），选哪个刻度先看它的尺寸界线是不是伸到了这面墙；
  5. 坐标精确到 0.5mm（245、225 这种奇数墙厚，中线在半毫米上，两侧墙面才是整数）。
- 输出里看：`scale_from` 写着“尺寸数字（n/m 段读出）”；`dim_labels` 读出比例；`dim_conflicts` 是**图纸自己前后矛盾**的标注（例如分段加起来 12070、总尺寸写 12060；两道尺寸量同一段一个 2770 一个 2775）——这些地方不可能同时满足，按“细部尺寸优先”处理，交付时要逐条告诉用户。
  `cad.json` 的 `dims[]`：每条尺寸线的 `labels`（读出的数字，`?xxx` = 没读准）和 `segs`（最终坐标量出来的长度），两者逐段相等才算对上；`cad.png` 上每段标注旁边写着读出的数字（绿 = 读出且一致，红 = 没读出）。
- 读不出数字（扫描件转的 PDF、字体特殊）时会退回整体比例：这时要加 `--total-width`，并在交付时说明尺寸是按图形量的、不是按标注。
- `cad.png`：毫米网格 + 墙段（红 = 实心承重、紫 = 填充新砌、绿 = 描边隔墙、蓝 = 窗带）+ 墙线 W 编号 + 洞口 O 编号和类型 + 符号 + 尺寸刻度，坐标直接就是 mm。
- `cad.json`：`openings[].why` 写着每个洞口的判断依据；`walls[].free` 是悬空端；`dims` 是尺寸线刻度（mm），可以和图上数字逐段对。
- `draft.json`：**基本可以直接用的 HouseSpec**——墙（含 `flush`、`status: new`、`bearing`）、门窗（有弧线的门带 `hinge` / `into`）、管井 / 地漏 / 柱、房间名（有文字层时）、底图。
  写生成脚本时**读入 draft.json 再补改**，不要重新手写墙：补房间名、把 `hole` 按房间功能换成门并定开向、窗台高、家具（见 `reference/cad-conventions.md` 末尾的核对清单）。
- 实测（本 skill 自带回归）：装修公司原始结构图 PDF，101 段标注读出 100 段，94 段与设计器尺寸差 ≤1mm，其余 6 段全是图纸自身矛盾；装修公司原始结构图 PDF，墙体与手工逐面量取一致（≤10mm），16 个洞口全部识别、类型正确；DXF（天正图层、门弧、图案填充、标注）往返 16/16、墙体 0 误差；黑底打印的 PDF 墙体全对。

### 3. 写完整的 HouseSpec

（CAD 路线：读入 `cad/draft.json` 后只做补改，跳过下面第 1、2 条。）

推荐写一个小的 Python 生成脚本，不要手写 JSON。参考 `reference/example-gen.py`：用像素写墙，脚本统一换算成 mm。
1. **像素 → 毫米的换算（尺寸精度的关键）**：图上有分段尺寸标注时，一定用 `scripts/axismap.py` 按标注定位，不要只乘一个整体比例——
   户型图本身画得不准，整体按比例换算每面墙会差 20~80mm，标注数字才是准的。做法：
   - 在 `dims_px.top`（或 bottom）里挑一条分段尺寸线，按 analysis.png 上的刻度编号，把相邻刻度之间的标注数字读出来；
     刻度多出来的（文字、墙角误检）跳过，少的照原图补上像素位置。左 / 右侧同理得到竖直方向。
   - `X = Axis(chain(刻度像素, 各段毫米))`、`Y = Axis(chain(...))`，生成脚本里用 `X(px)`、`Y(px)` 代替 `(px-OX)*S`；`X.report()` 会标出读数可疑的段。
   - 看清标注量的是墙面还是轴线：量到墙面（净尺寸）时，墙中线 = 墙面 ± 墙厚 / 2。
   - 完整示例见 `reference/example-gen-precise.py`：两条尺寸线合成一个 `Axis`，墙写成 `(墙面像素1, 墙面像素2)` 时中线和墙厚都直接取标注；同一条墙线上黑色段、灰色段分开写（承重 / 非承重不同）。
   - 墙按标注修正后，靠墙家具会被设计器自动推出墙面（嵌入 ≤120mm 的），不用逐个改坐标。
   - 图上没有分段标注、只有总尺寸时，才退回整体比例：从 `analysis.json` 拿 `mmPerPx` 和外轮廓左上角像素 `outline_px[0..1]` 作为 S、OX、OY。
2. 对照 `analysis.png` 的像素标尺和 `segments_px`（每段墙的 line = 中线像素位置），逐面列出墙：外圈闭合，内墙端点落在别的墙中线上。
   墙厚按图上的像素厚度 × 比例取整（常见 240 / 200 / 120 / 100）。
3. 门窗：`from`/`to` 取洞口两端的像素。门要填 `into`（门开进去的那个房间里的一点）和 `hinge`。
4. 房间标签放在原图房间名的位置。
5. 承重 / 非承重按原图图例逐面核对（`bearing_unsure` 里的墙必须看）。
   同一直线上厚墙接薄墙（外墙段接隔墙、黑色段接灰色段）：设计器会按“没有垂直墙的那一侧平齐”自动处理；两侧都有 / 都没有垂直墙的交接点（外墙中段变薄、十字交叉）看原图哪一侧墙线连续，给薄墙手写 `flush`（格式说明“面齐平”）。交付前在 plan2d 截图里放大每个厚薄墙交接点确认没有错台。
6. **墙的位置和厚度按原图量墙面，不要按刻度猜**：`scripts/wallfit.py` 逐面墙量两个墙面（涂黑墙量黑块边、描边墙量两条线），给出中线和厚度。
   刻度常是轴线，墙不一定居中在轴线上（差 3~6px 就是几十毫米的错台）；外墙常比内墙厚（如 300 vs 200）；
   **描边画的非承重墙往往和同一直线上涂黑的承重墙一样厚、墙面对齐**，不要默认给 100。同一直线上厚度不同的两段，看原图哪一侧墙线连续，给薄的那段写 `flush`。
   check 会报「墙面错台」（房间里看得到的那一侧墙面没对齐），必须清零。
6. 再用标注尺寸核对一遍（下一步自查会把设计器算出来的尺寸列出来，逐个对数）。

### 2D. 整栋楼、复式与别墅

遇到多楼层、描边墙断开、楼梯、电梯、挑空或别墅布置时，读取 [整栋楼工作流](reference/building-workflow.md)。其中包含 cadsplit 命令、坐标对齐、楼梯判读与净空检查；多层应生成一个 HTML。

### 4. 生成并自查（循环直到通过）

```bash
python scripts/build.py <工作目录>/spec.json -o <工作目录>/check.html
node scripts/check.mjs <工作目录>/check.html <工作目录>/check --strict
```

`--strict` 遇到警告、错误、丢墙、丢门窗、悬空墙端或标签落在房间外时退出码为 2，不能当成通过。需要查看原图固有的半截隔断等例外时，可不带 `--strict` 生成诊断报告，逐项说明例外，不能声称严格验收通过。

`report.json` 逐项看：
- `freeWallEnds` 应为空（悬空的墙端 = 墙没接上，房间会漏成一片）。确实有半截墙（比如玄关隔断）时可以保留。
- `rooms`：每个房间都识别出来了，名字对，面积和原图标注接近（这里是净面积，一般比原图标的小一点）。出现“（未命名）”说明漏了标签，或者有墙没连上。
- `wallsDropped` 必须为空：spec 里写了、方案里却没有的墙（两面平行墙只差十几毫米时会被吸附吞掉——让它们落在同一条线上）。
- `labelsOutsideRooms`、`openingsDropped` 应为空或 0（门窗放不下会被丢掉：洞口比墙段还长）。
- **尺寸逐个对数**：`exteriorDims` 是设计器按墙算出来的外围三道尺寸（`openings` 门窗分段、`axis` 墙厚 + 净距、`total` 总长），
  `rooms[].size_mm` 是矩形房间的开间 × 进深。和原图标注逐个比，**差 30mm 以上就回去改对应的墙**（多半是刻度读错、墙厚取错、或该用墙面却用了中线）。
  房间面积现在是按墙面精确算的净面积，和原图标的面积通常差 1% 以内（原图有的按轴线算，会偏大一点）。
- `errors` 必须为空。

**一定要看截图**：`overlay.png` 是生成的户型叠在原图上（半透明），墙、门窗位置应当和原图重合。`plan2d.png` 看门的开向，`view3d.png` 看整体。
发现偏差就改生成脚本，重新 build 和 check。一般 2–3 轮就能对上。

### 5. 布置家具、家电和水电（默认要做）

**原图画了家具 / 布置的，必须一比一还原**：每件家具的类型、位置、尺寸、朝向照图放（床多宽、桌子是椭圆还是方的、沙发几段怎么拼、柜子分几段、卫生间玻璃隔断和门在哪），图上画了的不能漏、不能用近似件凑；家具库没有的类型，需要先取得本仓库未包含的 designer 源码，再补进项目（`src/catalog.ts` + 2D `src/draw/symbols2d.ts` + 3D `src/view3d/furniture3d.ts`，`npm run skill:sync`）和格式说明。
同时要能用：门扇打得开、每个房间和门都有 ≥ 700 的通道，人能走进去。图上画法真的走不通的（比如岛台和橱柜之间只留了几十毫米），按能走通的最小改动处理，并在交付时逐条告诉用户改了哪里、为什么。
读图要点（容易认错的画法，拿不准就放大 4 倍逐个看，必要时查资料）：
- 厨房里被橱柜三面围住的大矩形多半是**地面**（U 形厨房的站人区），不是岛台——岛台四周一定留着 ≥ 800 的通道；
- 洞口边线上一段加粗的短线 / 两头短竖线 = 推拉门轨道（玻璃推拉门、隐形门），要建墙 + `sliding` / `pocket`，不是空着；
- 卫生间里一条窄框 + 三个小圆 + 带斜线的小方框 = 嵌入式淋浴（`showerSet`），旁边的小圆是花洒、带十字的圆是地漏；
- 靠墙一条细长圆角框、前面没有电视屏幕符号（梯形 / 加粗短线）的，是矮柜 / 边柜，**不要当电视柜**；沙发背对的那面墙不放电视；
- 单人椅、沙发：加粗的双线 / 厚的那一边是靠背，椅子面朝茶几、餐桌；
- 门扇：门轴在弧线圆心，开向看弧线在哪一侧；门开在哪面墙看门框短线，套房卫生间的门常开在卧室里而不是走廊；
- 沙发是弯的 / 折角 / 蛇形的用 `bendSofa` 按中线描，不要拿直沙发或 `curvedSofa` 近似。
- 墙边的细带也要认：贴墙一条带等距刻度 = 木格栅护墙板，床头那面墙的双线 = 床头背景板 / 软包，都用 `wallPanel`；墙位置上一条分格细长条 = 玻璃隔断 `glassWall`；小灰圆 = 地漏（`structs` 的 `drain`，按图上的位置放）；墙垛、柜子端头的小圆角柜这些零碎也照画。
- 斜墙（非 90° 的转角）设计器会按墙面求交斜接，不用手工凑；画完放大看一眼转角。
- **一个地方一个地方地对**：furnoverlay 把墙（绿 = 承重、青 = 非承重，按厚度画）、门窗洞口（黄）、家具外框（红 / 蓝）都画回原图，按房间切块逐张看，原图上每一笔都要能在叠图里找到对应的东西。
核对方法：
```bash
python scripts/furnoverlay.py <工作目录>/spec.json --out <工作目录>/furncheck   # 家具外框画回原图（红 = 落地，蓝 = 挂墙 / 吸顶，箭头 = 正面）
```
逐块看 `furn_r*c*.png`：每个框要正好压在原图那件家具的轮廓上，原图上有而没有框的就是漏了。

除非用户只要结构，否则按房间功能放一套完整的家具和家电，让打开就像真的住进去（家具 key 和朝向规则见格式说明）：
- 卧室：床、床头柜、衣柜、挂机空调、窗帘；儿童房可换上下床 / 婴儿床，书房放书桌椅、书架
- 客餐厅：沙发（或 L 形沙发）、茶几、电视柜或壁挂电视、地毯、餐桌椅、餐边柜、柜机或挂机空调、落地窗帘；入户放鞋柜（可加换鞋凳）、饮水机
- 厨房：整体橱柜（含水槽灶台烟机）、冰箱；空间够加洗碗机、电器高柜；燃气热水器常挂在厨房或阳台
- 卫生间：马桶、浴室柜、淋浴房或一字隔断、电热水器（挂在马桶/淋浴上方，或用燃气热水器）、浴霸、毛巾架；放 `sewer` 下水口和 `drain` 地漏
- 阳台：洗衣机（+ 烘干机）、晾衣架、洗衣池柜，放地漏
- 别墅：车库（车、充电桩、储物架、工具台）、庭院（草坪、汀步、泳池、凉亭、车棚、乔木、灌木、草坪灯、烧烤台、景墙、秋千、躺椅、遮阳伞、大门）、休闲（台球桌、麻将桌、茶台、影院沙发、三角钢琴、吧台、桑拿房、挑空大吊灯）、设备（壁挂炉、分集水器、软水机），见上面“独栋别墅”
- **按现实装修的常理摆**（设计器是正式装修前的预看，每样东西都要真能这么装）：
  - 挂机空调、热水器、壁挂炉、吊柜、电视、镜柜、装饰画只能挂在**实墙**上，不能挂在窗洞 / 窗帘盒 / 门洞的位置，也不能和窗帘叠在一起；空调优先放靠外墙（好打孔走管）的侧墙，房间里没有合适实墙时放在床头墙上方，别对着门
  - 橱柜窗前那段不做吊柜（`kit.wallLegs` 只写其他段）；燃气热水器挂在厨房靠外墙的窗边实墙上
  - 每个卫生间都要有热水来源：离厨房燃气热水器近的共用，远的各放一台电热水器（挂在马桶上方或淋浴区旁边的实墙上，不要挂在浴室柜镜子上方）
  - check 会报「挂墙位置」「橱柜吊柜挡住窗户」，必须清零
- 窗帘：住人的房间（卧室、客餐厅、书房、茶室……）每扇窗都放落地窗帘，**宽度必须盖住整个窗洞，两侧各多出 100~200**；转角窗两面墙各放一幅；落地窗 / 窗紧挨着阳台门的，一幅连门一起盖住。check 会报「窗帘没盖住窗户」
- 软装点缀：绿植、地毯、装饰画、落地灯；家具库 160 多件，按户型面积和风格挑（U 形 / 弧形沙发、圆餐桌、卡座、酒柜、L 形橱柜、双盆浴室柜、独立浴缸、猫爬架等都有，见格式说明）
- 地面铺装：默认用 `mat` 预设；用户说了具体的砖（“客厅 800×800 灰色大板”“卫生间 300×300 斜铺”“主卧人字拼木地板”），写进房间的 `tile`（格式见格式说明“自定义铺砖”），设计器会按砖的尺寸、缝宽和铺法一块块铺，报价按排出来的片数算
- 用户点名想要的效果风格（沙盘效果图、彩平图、奶油风、原木、莫兰迪……）写进 spec 的 `look`
- spec 里写 `"autoElec": true`：设计器按房间、门窗和这些家具自动生成全套水电点位并关联开关（餐桌 / 岛台上方吊灯、各功能区灯、全屋覆盖补筒灯不留暗区、插座按墙长补齐，规则见格式说明），一般不用手写 elec
- 管线自动排布（不用写）：水电图层上自动排出强电插座回路、照明回路、网线、冷热水、排水的走线，并给出回路表（断路器 / 线径 / 长度）和材料清单，规则与规范依据见 `reference/mep-rules.md`。所以**强电箱、弱电箱、管井、下水口、热水器要放对**：缺强电箱排不出电路，缺弱电箱排不出网线，没热水器没有热水管，排水接管井 / 下水口。autoElec 会自动放进水总阀（`waterIn`），知道实际进户位置就手写。**别墅 / 复式**：总箱在有入户门那层，其他层是分层配电箱（自动算干线）；进水总阀只放在入户层，其他层由给水 / 热水立管接上来（立管放管井，没有就放在上下层对齐的用水点），所以上下层的卫生间、厨房、管井要按图对齐放准；壁挂炉也算热源；挑空、楼梯井上不走地面管线；有庭院 / 车库的首层排水直接出户。全楼材料清单在水电面板导出
