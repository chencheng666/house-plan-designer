# 设计助手 2.0

入口在生成网页右下角“设计助手”。扩展和主设计器共用当前楼层数据；无需服务端或联网。`build.py` 默认注入，可维护源码在 `assets/assistant/`，模板适配器在 `scripts/assistant_bundle.py`。

## 十二个功能页

| 页面 | 实际操作与输出 |
|---|---|
| 生活需求 | 填家庭成员、工位、鞋量、挂衣量、通行目标；核对工位和收纳容量 |
| 开放分区 | 在 2D 顺次点轮廓、退点、取消或完成；独立命名、材质、灯具；不增加墙体；地面网格在 3D 实际呈现，灯写入水电点位 |
| 动线净距 | 旋转家具操作包络、床侧、门扇检查；按目标净宽从入户至各房间搜索；2D 彩色标记与定位 |
| 收纳 | 柜体扣板厚的内空估算，归属、用途、层数、挂衣延米；鞋柜和挂衣用途分别计量，按人汇总 |
| 方案对比 | 保存整栋方案与真实三维截图；两方案图片、面积/收纳/点位/预算并排比较；新增/删除/移动平面标记；恢复前自动快照；三方合并逐字段选择冲突 |
| 模型材料 | 导入静态 GLB / glTF + 配套 bin/贴图；真实网格替代占位体并随原家具拖动、旋转、缩放；材料贴图、报价、品牌型号、组合标签 |
| 预算 | 当前层面积和数量联动；主材、人工、主材损耗、运费、补充费用与上限；从用户材料库选同单位报价及替代材料；CSV |
| 采光视线 | 纬度/月/太阳时/北向写回原三维日照；窗地比、中心距窗、采光进深估算；方位角遮挡及逐小时太阳判断；入户直视床/马桶、沙发电视距离及角度 |
| 深化设计 | 实际柜格与柜体尺寸修改；柜体正立面 SVG；实际灯具情景保存恢复；点位坐标 CSV；窗帘盒/踢脚线/拼缝剖面 SVG |
| 采购施工 | 按开工日生成可编辑工期、已询价采购计划；负责人、日期、状态、前置和验收要求；实测记录、照片；CSV/ICS |
| 批注协作 | 绑定当前对象或视口位置、负责人、期限、处理状态、实际截图；离线批注包导出合并；同时间冲突另存记录 |
| 工程交付 | 整栋完整工程包、便携 HTML、分区平面 SVG；识别证据/置信状态、轴线/净尺寸/外包尺寸链复核；源修订检测及旧编辑检查点比较 |

## 精度和保存边界

- 不通过打隔墙来创建功能分区。用户要求书房与客厅、家政与厨房打通时，保留其连续空间，可用分区名、照明和材质表达用途。`material: none` 保持原铺装。
- 家庭信息、报价、城市、方向没有依据时保留“待填写/待询价/待核实”。默认人数或纬度仅是界面起始值。估算提醒不代表施工验算结论，不自动拆墙或移动家具。
- 动线为 **100 mm 网格**、家具与结构实体避障、门洞畅通假设。细窄通道受网格和模型尺寸影响；图中家具前方的座椅等可能是预期布置，使用者需复核操作区提醒。原检查器的错误/警告与助手的布置建议分开验收，不能通过隐藏提醒宣称布局合理。
- 太阳为所填月份 21 日的简化模型，使用当地太阳时；遮挡为方位角范围和高差/距离。没有专业照度、反射、多反弹或法定日照时数计算。
- 墙面预算为墙轴双面毛面积，未扣门窗、外墙及实际贴面范围。内空容量、鞋位和挂衣估算使用页面列出的板厚及尺寸假设。待询价项必须列出，不能把已计价合计当全装修总价。
- GLB / glTF 仅支持普通静态网格。骨骼动画、Draco、KTX2 需先转换。外部引用只在本次用户选择的配套文件中查找，缺文件或远程依赖明确报错，不静默回退为“导入成功”。
- 小数据保存在当前楼层 `plan.enhancements`，原生自动保存、撤销、楼层切换仍适用。大资产、快照和恢复记录在 IndexedDB；存储失败会明确报错。原生 JSON 不含大资产，跨设备请用 **完整工程包、便携 HTML 或原生分享 HTML**。
- 便携 HTML 有独立存档键，只首次载入内嵌工程，之后刷新保留继续编辑。原生分享沿用原分享横幅及确认流程，同时携带助手资产。
- 快照恢复覆盖整栋方案，恢复前自动留一份备份。对比、预算和分析指标按快照的当前层。3D 对比为保存的真实图片，仍可恢复对应方案进一步漫游，并非两个实时渲染器。
- 稳定标识初始按几何和类别生成，原生编辑过程中保留；跨设备原生随机 ID 不会制造整屋差异。源图本身改变对象位置/类别时仍可能显示新增/删除，合并前必须查看差异及引用完整性。
- 源修订更新不自动覆盖旧编辑；原生提交后延迟写入编辑检查点，下一修订可从工程交付加入比较或下载恢复包。关键交付仍下载完整工程包，浏览器数据不是唯一备份。
- 开放分区与节点 SVG 是新增辅助输出；原生 PDF / DXF 仍导出主设计器的施工图层，不把助手的视口标记冒充正式施工图。协作是文件交换，无远程实时同步或自动发送。

## 在 HouseSpec 里预置

顶层支持 `projectId`（同一工程保持不变）及 `assistant`（各层默认助手配置）。不填则自动按源文件路径生成工程标识。常见字段：

```json
{
  "projectId": "我的住宅-01",
  "assistant": {
    "zones": [{"id":"study","name":"开放书房","points":[{"x":100,"y":100},{"x":2100,"y":100},{"x":2100,"y":2100},{"x":100,"y":2100}],"material":"none","color":"#789d8a","lights":0}],
    "evidence": [{"id":"shaft","name":"设备方框","confidence":"待核实","source":"原户型图无说明","note":"保留原位，待结构图核实"}],
    "dimensions": [{"id":"chain1","name":"横向轴线","basis":"墙轴","x1":0,"y1":0,"x2":4000,"y2":0,"expected":4000,"tolerance":20,"visible":false}]
  }
}
```

分区至少三点，无自交、无重复拐点，最小面积0.01㎡。坐标单位 mm。可用 `core.mjs` 的 `defaultState()` 看完整配置，`profile/costs/storage/materials/models/scenes/tasks/notes/sections/environment` 均对应功能页。资产必须通过文件导入或完整工程包携带，不能只填一个不存在的资产 ID。

## 验收与同步

```bash
python -m unittest discover -s scripts/tests -p 'test_*.py'
node --test scripts/tests/*.test.mjs
node scripts/qa-assistant.mjs 设计器.html 新的助手验收目录
python scripts/qa_files.py 新的助手验收目录/downloads
node scripts/qa.mjs 设计器.html 新的完整验收目录
python scripts/qa_files.py 新的完整验收目录/downloads
node scripts/qa-extra.mjs 设计器.html 新的光追验收目录 --only=pdf,pt --pt-complete
```

助手验收覆盖24项，包括真实 GLB/glTF 导入、实际三维贴图、资产完整工程包、独立存储恢复、便携二次编辑保留、原生分享、稳定 ID、修订恢复和390宽屏。不得把纯函数测试替代真实交互；不得将20项旧报告写成24项通过。完整验收覆盖原有110项；光追自动完成另用 `--pt-complete` 验证真实计数。

适配器同时校验已知模板SHA256、桥接及分享接口的唯一匹配，未知上游版本停止构建。`assets/template.html` 保留已有 PDF 和光追修复；扩展源码不直接写进压缩包。同步安装时一起复制 `assets/assistant/`、`scripts/assistant_bundle.py`、`build.py`、本说明及验收脚本，保留安装目录的 `.venv` 与 `scripts/node_modules`。
